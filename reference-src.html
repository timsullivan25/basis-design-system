Basis Design System

A design system for a hedge fund platform running quantitative and fundamental strategies. Dense, fast, light on chrome, organised in layers: a summary you absorb in one glance, with a way deeper on every surface. This page is the complete reference — guidelines, foundations, every component with live examples, and the full token source.

Provenance. This system was authored from a written brief — no company name, logo, font files, screenshots, Figma file or codebase were supplied. "Basis" is a working name, there is no logo (the name is set in Archivo Bold at −0.03em), and Archivo / Roboto Mono / Newsreader are Google Fonts stand-ins. Lucide is a flagged icon substitution. Everything else is derived from the brief.

Content fundamentals

Voice. Neutral, specific, unhedged. The interface states what is true and where the number came from; it does not congratulate the user or explain itself twice.

Person. No "I". Second person only for the user's own artefacts — "Your screens", "Saved to your workspace". System state is impersonal: "Prices delayed 15 minutes", not "We're having trouble".

Casing. Sentence case for everything readable — headings, buttons, dialog titles, alert text. UPPERCASE only for micro-caps labels: field labels, table column headers, KPI labels, popover header strips (11px, 600, 0.07em tracking). Never title case.

Numbers carry the meaning, words carry the context. A label names the measure, the figure states it, a short clause states its provenance: NET EXPOSURE / 42.8% NAV / −1.4% vs prior close / 16:00 ET. Every derived figure gets a methodology note — a column description, a Tooltip, or a Popover — never a footnote asterisk.

Units. Percentages to 1–2 decimals; contribution and spreads in bps; notional with thousands separators; currency stated once in the header, not per row. Signed values always carry their sign using a true minus (−, U+2212), not a hyphen. Timestamps are exchange-local with the zone (16:00 ET). Settlement basis stated where it matters (T+1).

Empty and error states say what is missing, then what to do: "No positions match these filters. Clear one to widen the set." Never "Oops" or "Something went wrong".

Length. Buttons 1–3 words. Badges 1–2 words. Alert titles under 60 characters with detail in the body. Analyst prose is the one place sentences run long, and it is set in the serif to signal a human wrote it.

Emoji: never. Not in UI, not in labels, not in commentary.

Visual foundations

Palette. Cool near-black ink for text and structure; electric corporate blue #0B4FD9 as the single action colour; light blue #1D9BC7 as secondary brand and second data series. Green and red are reserved for direction of value, never decoration. Amber is caution only. Violet appears only in charts. At most one accent surface per view; the page is --ink-50, cards are white.

Type. Archivo throughout the UI; Roboto Mono for every figure, always tabular; Newsreader for analyst prose. Body 13px, labels 11px uppercase, KPI figures 22px mono, display 28–48px.

Density. 2px base scale. 8px is the default gap inside a control, 12–16px between elements, 24–32px between sections. Control heights 20/24/28/34/40 with 28px default — deliberately ~20% tighter than Material's 36–40px baseline. Table rows 30px, 26px dense. This compactness is the core promise: more information per screen without shrinking type below 11px.

Backgrounds. Flat colour. No decorative gradients (the only gradients are the 18%→0% fills under sparklines and line charts), no photography, no illustration, no texture, no pattern, nothing full-bleed. A surface that needs to recede goes to --surface-sunken, not to an image.

Cards. White surface, 1px hairline, 5px radius, flat — no shadow in page. Optional 34/40px header with icon, title, subtitle, right-aligned actions; optional muted footer for as-of stamps and provenance. Elevation signals floating, not importance: shadow-1 on controls, 2 on hover lift, 3 on popovers, 4 on dialogs.

Borders and radii. Structure is carried by hairlines, not shadows. 2px chips and checkboxes, 3px inner elements, 5px controls and cards, 8px dialogs, pill for tags and meters. Nothing more rounded than 8px carries content. A 2px top border on a MetricCard is the only coloured-edge pattern, and only for status.

Animation. Fast and decelerating. 80ms hover/press, 120ms colour and focus, 180ms expand, 260ms chart draw, 400ms route change. Default easing cubic-bezier(.2,.8,.3,1). One bounce in the whole system: the Switch knob. Fades and 4px rises for entrances; no slides across the viewport, no parallax, no looping motion except the spinner. prefers-reduced-motion disables all of it.

States. Hover tints a surface one step and never changes colour family; text goes one step darker; primary buttons darken to blue-800; drill-in affordances turn blue and nudge their chevron 1px. Press is a 0.5px downward nudge plus one darkening step — no scaling, no ripple. Focus is a 3px blue ring at 20% plus a blue border, on :focus-visible only. Selection is blue-50 fill with a blue-300 border.

Transparency and blur. Rare and functional: dialog scrim at 40% ink with a 2px backdrop blur; --blur-panel for floating panels over live data. Never on cards, headers or charts — blur costs legibility and legibility is the product.

Layout. 216px left rail (48px collapsed), 44px top bar, 34px sub-bars, 320px right drill-in panel, 16px gutters, content max 1440px. Rail, top bar and tab bars are fixed; only the content column scrolls; table headers are sticky. Nothing floats over content except popovers, tooltips, dialogs and toasts.

Charts. Horizontal gridlines only; no plot background, no chart borders, no 3D, no drop shadows. Axis figures 9px mono. Benchmarks always dashed --chart-benchmark. Categorical series take --chart-1..12 in order. Legends sit above the plot and carry the latest value so they double as a readout.

Imagery. There is none, by design. Where a brand would put a photo, this system puts data.

Dark mode. Same tokens remapped under [data-theme="dark"]: #080B10 app, ink-900 cards, action lightens to blue-600, up/down brighten to #3FBE8C / #F0637F. Light mode is the default and the primary design target.

Iconography

  • Set: Lucide 0.469, 2px stroke, 24×24 grid — a flagged substitution, chosen for even stroke weight and small-size legibility.
  • Delivery: the Lucide UMD bundle; Icon renders inline SVG from the library's icon data so glyphs inherit currentColor. Nothing is drawn by hand.
  • Sizes: 12px in table cells, 14px inside controls, 15–16px in nav and card headers. Never larger than the text beside it, never above 16px in app chrome.
  • Colour: --text-secondary or --text-tertiary by default; --text-brand for active and drill-in states; status colours only inside Alert and Badge.
  • Usage: an icon is context, not decoration. Every icon sits beside a label or is an IconButton with a label. No icon-only navigation, no icon grids, no illustrated empty states. Emoji never; the only unicode-as-icon is the true minus sign.
  • Vocabulary: layout-dashboard overview · table-2 positions · gauge risk · filter screens · line-chart/bar-chart-3/pie-chart charts · scale exposure · trending-up/trending-down direction · alert-triangle breach · info methodology · download export · settings-2 configure · search find · chevron-right drill · cpu quant · globe macro · file-text notes · briefcase fund.

Layering & modularity

Every screen follows the same law. Layer 1 is summary tiles and collapsed rows — absorbed in one glance. Layer 2 is tables and charts. Layer 3 is drill-in panels, expanded rows and methodology popovers. Nothing important lives only at Layer 3; a figure that matters always has a Layer 1 or 2 signal pointing at it.

Modularity works the same way twice: a module can stand alone or be extended to capture nuance by strategy, security type or company type. In the UI that shows up as "extend from" — inherit a parent's criteria, override what differs, keep the lineage visible.

Intentional additions beyond a standard set

  • Icon — wrapper for the glyph set; keeps sizes consistent and makes the icon source swappable in one file.
  • Field — shared label/hint/error scaffold so micro-caps labels stay consistent.
  • SegmentedControl — period and view switching is constant here; a Select would be slower and taller.
  • DeltaValue, Sparkline, MetricCard, DataTable — the summary→detail layering is not expressible with generic primitives.
  • ChartLegend, LineChart, BarChart, DonutChart, BarMeter — shipping an extended chart palette without chart components would leave the most important surface undefined.
  • Accordion, Popover — the "dig deeper without leaving the view" requirement.
